# AppVault API

Простой файловый HTTP-сервер на Go для LocalVault. Проект разработан с помощью ИИ.

Сервер хранит один файл и поддерживает два запроса к `/vault` — GET возвращает его байты, POST атомарно заменяет их. Обе операции требуют API-токен. Клиент расшифровывает файл после ввода мастер-пароля и отправляет каждое сохранение уже зашифрованным.

## Первый запуск

Сначала экспортируйте зашифрованное хранилище из LocalVault. Создайте новый серверный каталог из этого файла:

```sh
./appvault-api init -data ./data -vault ./export.lvault
```

Команда сгенерирует случайный 256-битный токен и один раз выведет его в консоль. Сохраните токен и введите его в LocalVault при настройке URL-источника. На сервере в `credentials.json` хранится только SHA-256 токена. GUID и идентификаторы файлов не используются.

Запустите сервер:

```sh
./appvault-api serve -data ./data -listen 127.0.0.1:8080
```

В LocalVault откройте **Настройки** на экране авторизации, укажите URL вида `https://vault.example.com/vault` и API-токен, затем введите мастер-пароль. Адрес сохраняется на устройстве, токен запоминается с защитой средствами ОС. На Windows используется DPAPI текущего пользователя, на Linux — Secret Service через `secret-tool` (пакет `libsecret-tools`). При смене URL или сбросе пути сохранённый токен прежнего источника удаляется.

На Windows используйте `appvault-api.exe`.

## HTTPS

Для доступа через интернет используйте HTTPS. Токен передаётся в заголовке Authorization, а TLS защищает его при передаче. Можно оставить сервер на `127.0.0.1:8080` за HTTPS-прокси или включить TLS в самом сервере:

```sh
./appvault-api serve -data ./data -listen :8443 -cert ./fullchain.pem -key ./privkey.pem
```

HTTP на `127.0.0.1` подходит для локальной проверки. Клиент проверяет сертификат HTTPS-сервера и запрашивает конечный URL напрямую.

## Смена токена

Остановите сервер, выполните команду и запустите его снова:

```sh
./appvault-api rotate-token -data ./data
```

Новый токен выводится один раз. Команда обновляет только серверные учётные данные. Клиенты вводят новый токен при следующем подключении.

## Протокол

GET и POST принимают заголовок `Authorization: Bearer <token>`. Сервер не передаёт токен и его хэш клиентам. Токен позволяет получить и заменить зашифрованный файл. Для чтения самих записей нужен мастер-пароль.

GET возвращает `application/octet-stream`, `Cache-Control: no-store` и сильный ETag в виде SHA-256 файла в двойных кавычках. POST отправляет весь зашифрованный файл и заголовок `If-Match` с ETag последнего открытия или сохранения. При успехе сервер возвращает HTTP 204 с новым ETag.

Если файл изменился на другом устройстве, сервер отвечает HTTP 412. LocalVault сообщает о конфликте и отменяет текущую локальную правку. Заблокируйте и снова откройте хранилище, чтобы получить актуальные записи. Сервер последовательно обрабатывает записи и допускает только один процесс, работающий с его каталогом.

Максимальный размер файла — 16 МиБ плюс 156 байт заголовка и криптографических служебных данных. Сервер рассматривает содержимое как непрозрачные байты и не расшифровывает его.

Импорт в клиенте заменяет содержимое выбранного удалённого хранилища. Серверный API-токен при этом сохраняется в отдельном файле `credentials.json`.

## Сборка и проверка

Нужен Go 1.24 или новее. Внешних Go-зависимостей нет.

```sh
go test ./...
go test -race ./...
go vet ./...
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o appvault-api .
```

Для Windows из PowerShell:

```powershell
$env:CGO_ENABLED = '0'
go build -trimpath -ldflags='-s -w' -o appvault-api.exe .
```

Сборки Linux x64 и Windows x64 используют стандартную библиотеку Go.
