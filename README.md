# LocalVault

LocalVault — локальный менеджер паролей для Windows и Linux на C++17 и Qt Widgets. Проект разработан с помощью ИИ.

## Быстрый запуск

Скачайте архив для своей ОС со [страницы релизов](https://github.com/sudzekai/LocalVault/releases) и полностью распакуйте его. Обе сборки включают Qt, плагины и криптобиблиотеки.

- **Windows x64.** Запустите `LocalVault.exe` из распакованной папки.
- **Linux x64.** Запустите `./LocalVault` из распакованной папки. Требуется графический сеанс и Linux с glibc 2.36 или новее (например, Debian 12). Устанавливать отдельные пакеты Qt и криптобиблиотек не требуется.

Создайте хранилище с мастер-паролем длиной от 12 символов или импортируйте зашифрованную копию. Хранилище находится в `%LOCALAPPDATA%\LocalVault V2\vault.lvault` на Windows и в `${XDG_DATA_HOME:-$HOME/.local/share}/LocalVault V2/vault.lvault` на Linux.

Чтобы работать с существующим файлом `.lvault` напрямую, откройте **Настройки** на экране авторизации и укажите путь к файлу. Путь сохраняется между запусками на этом устройстве. Если файл недоступен, приложение покажет ошибку и сохранит выбранный путь. Кнопка **Сбросить путь** возвращает стандартное расположение. Перед открытием одного файла на другом устройстве заблокируйте хранилище или закройте приложение.

Вместо пути можно указать URL собственного [AppVault API на Go](server/README.md) и API-токен. Адрес сохраняется между запусками, токен запоминается с защитой средствами ОС: Windows DPAPI или системная связка ключей Secret Service на Linux. Каждое изменение сразу отправляется на сервер в зашифрованном виде. Сервер проверяет токен для чтения и записи, а ETag защищает от перезаписи изменений другого устройства. Для подключения через интернет используйте HTTPS.

Для создания сайта нажмите ПКМ по пустой области левой панели и выберите «Добавить сайт». Этот же пункт в меню группы создаёт сайт внутри неё. Укажите название и адрес сайта. Панель слева показывает сайты по алфавиту, а поиск фильтрует их по названию. Выберите сайт, чтобы увидеть карточки его аккаунтов. Добавление, просмотр и редактирование аккаунтов доступны через кнопки с подсказками.

Для создания группы нажмите ПКМ по пустой области левой панели и выберите «Создать группу». В этом же меню есть создание сайта. Группы отображаются в общем списке слева, нажатие ЛКМ по группе или её стрелке раскрывает и сворачивает вложенные сайты. При выборе группы в основной области показаны карточки её сайтов. Изменение и удаление группы доступны через ПКМ по ней. Сайты без группы показаны в общем списке отдельно. При удалении группы её сайты и аккаунты сохраняются. Для группы и сайта можно выбрать иконку из полного встроенного каталога Bootstrap Icons с поиском по названию.

У аккаунта есть локальный ID и логин. Укажите пароль или включите «Альтернативный способ входа» и опишите его, например «OAuth через Google». При альтернативном входе пароль необязателен. Можно указать имя пользователя, телефон, дату создания и несколько адресов электронной почты с описаниями. Для нового аккаунта дата по умолчанию соответствует моменту сохранения. Её можно изменить или убрать.

В карточке каждого аккаунта можно сохранить запасные коды восстановления, по одному на строку. Они шифруются вместе с аккаунтом и скрыты до нажатия на глаз. Кнопка копирования использует очистку буфера обмена.

Пароли скрыты до явного показа. LocalVault очищает свою запись в буфере через 25 секунд или при блокировке, если буфер с тех пор не был заменён. Генератор поддерживает длину от 4 до 256 символов и включает хотя бы один символ из каждой выбранной группы. Индикатор стойкости даёт приблизительную оценку по длине и разнообразию символов. Таймаут автоблокировки по умолчанию составляет 5 минут и регулируется в пределах от 1 до 120 минут.

### Резервные копии

Экспорт сохраняет зашифрованную копию LocalVault V2. Импорт проверяет пароль и целостность копии, затем целиком заменяет текущее хранилище, включая настройки и мастер-пароль. Если старые записи нужны, сначала экспортируйте их. Уже экспортированные копии открываются мастер-паролем, действовавшим при экспорте. Утерянный мастер-пароль восстановить невозможно.

## Сборка

Требуются CMake 3.21+, компилятор C++17, Qt 6.4+ с Qt Widgets, Qt SVG и Qt Network, libsodium и OpenSSL 3 или новее для того же компилятора и архитектуры. AES-256-GCM выполняет OpenSSL с доступной на компьютере реализацией.

Пример для PowerShell с Qt MinGW, Ninja, OpenSSL и официальной статической библиотекой libsodium. Укажите пути к своим зависимостям. Компилятор, CMake и Ninja должны быть доступны в `PATH`.

```powershell
$qt = 'C:/Apps/Qt/6.12.0/mingw_64'
$sodium = 'C:/Dependencies/libsodium-win64'
$openssl = 'C:/Dependencies/openssl/mingw64'
$env:Path = "$qt/bin;$openssl/bin;$env:Path"
cmake -S . -B build -G Ninja "-DCMAKE_PREFIX_PATH=$qt" `
  "-DSODIUM_INCLUDE_DIR=$sodium/include" "-DSODIUM_LIBRARY=$sodium/lib/libsodium.a" `
  "-DOPENSSL_ROOT_DIR=$openssl" "-DOPENSSL_CRYPTO_LIBRARY=$openssl/lib/libcrypto.dll.a" `
  -DLOCALVAULT_SODIUM_STATIC=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
& "$qt/bin/windeployqt.exe" --release --translations ru build/LocalVault.exe
```

При распространении динамической сборки разместите DLL libcrypto рядом с EXE. Для динамической линковки libsodium укажите её импортную библиотеку, оставьте `LOCALVAULT_SODIUM_STATIC=OFF` и разместите DLL libsodium рядом с EXE. Тесты работают с отдельным временным каталогом и синтетическими данными.

Для сборки в Debian 12:

```sh
sudo apt install build-essential cmake ninja-build qt6-base-dev qt6-svg-dev qt6-translations-l10n libsodium-dev libssl-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
cmake --install build --prefix "$HOME/.local"
```

## Архитектура

| Компонент | Назначение |
| --- | --- |
| `AuthManager` | Создаёт параметры хранилища и проверяет мастер-пароль |
| `CryptoManager` | Получает ключи, шифрует и аутентифицирует содержимое |
| `StorageManager` | Проверяет формат, читает файл и атомарно заменяет его через `QSaveFile` |
| `PasswordManager` | Управляет сессией, записями, настройками и резервными копиями |
| `PasswordGenerator` | Генерирует пароли на основе криптографического ГСЧ libsodium |
| `MainWindow` | Управляет интерфейсом, сеансом бездействия и буфером обмена |

## Формат и границы защиты

Порядок полей формата 4 — сигнатура `LVLT`, версия (32 бита), параметры Argon2id (число проходов и память в КиБ, по 32 бита), 16-байтовая соль, 32-байтовое проверочное значение, 32-байтовый случайный параметр получения ключа файла, 12-байтовый nonce, шифротекст, 16-байтовый тег AES-256-GCM и 32-байтовая контрольная сумма SHA-256. Многобайтовые числа хранятся в big-endian.

В зашифрованном содержимом хранятся настройки блокировки, группы с названиями и выбранными иконками, сайты со ссылками на группы, а также аккаунты со ссылками на сайты. Адрес почты и его описание хранятся как отдельные поля. Дата создания записывается в миллисекундах от эпохи Unix или как маркер отсутствующего значения. Названия, URL, способ входа и все поля аккаунтов входят в зашифрованную часть.

Argon2id 1.3 использует 64 МиБ и три прохода по умолчанию. Из результата libsodium KDF выводит отдельные ключи для шифрования и проверки пароля. Проверочное значение — HMAC-SHA-256 заголовочных параметров. Для каждого сохранения используются свежие случайные nonce и параметр производного ключа файла. AES-GCM аутентифицирует заголовок и содержимое. Контрольная сумма помогает обнаружить случайные повреждения до проверки пароля. Проверку подлинности выполняет AES-GCM.

Расшифрованные данные обрабатываются в памяти. Ключи хранятся в защищённой и заблокированной памяти libsodium. Приложение очищает подконтрольные буферы при завершении работы с ними. Qt, система ввода и буфер обмена могут создавать собственные копии. Защита файла рассчитана на хранение в закрытом состоянии. Доступ к разблокированному процессу, системным дампам, снимкам экрана и данным буфера зависит от защиты ОС и запущенных программ.

Справочные материалы — [Argon2id в libsodium](https://doc.libsodium.org/password_hashing/default_phf), [разделение ключей](https://doc.libsodium.org/key_derivation), [AES-GCM в EVP OpenSSL](https://docs.openssl.org/3.5/man3/EVP_EncryptInit/), [защищённая память](https://doc.libsodium.org/memory_management), [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html).
