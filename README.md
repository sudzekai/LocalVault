# LocalVault

LocalVault — локальный менеджер паролей для Windows и Linux на C++17 и Qt Widgets. Проект разработан с помощью ИИ.

## Быстрый запуск

Распакуйте архив для своей системы со [страницы релизов](https://github.com/sudzekai/LocalVault/releases).

- **Windows x64.** Запустите `LocalVault.exe` из распакованной папки. Держите DLL и плагины рядом с EXE. В локальной папке проекта готовая сборка находится в каталоге `app`.
- **Linux x64.** Для Debian 12 установите зависимости командой `sudo apt install libqt6widgets6 qt6-qpa-plugins qt6-translations-l10n libsodium23 libssl3`, затем запустите `./bin/LocalVault` из распакованной папки. Для запуска через меню рабочего стола установите содержимое архива в постоянный префикс, например `~/.local`, и убедитесь, что его каталог `bin` входит в `PATH` графического сеанса.

При первом запуске задайте мастер-пароль длиной от 12 символов или импортируйте зашифрованную копию. На Windows файл хранится в `%LOCALAPPDATA%\LocalVault\vault.lvault`, на Linux — в `${XDG_DATA_HOME:-$HOME/.local/share}/LocalVault/vault.lvault`. Один экземпляр приложения работает с этим файлом одновременно. Автоматическая блокировка по умолчанию срабатывает через 5 минут. Таймаут можно изменить в настройках в диапазоне от 1 до 120 минут.

Пароли скрыты до явного показа. Для копирования используйте кнопки приложения. LocalVault очищает свою запись в буфере через 25 секунд или при блокировке, если буфер с тех пор не был заменён. Генератор поддерживает длину от 4 до 256 символов и включает хотя бы один символ из каждой выбранной группы. Индикатор стойкости даёт приблизительную оценку по длине и разнообразию символов.

### Резервные копии

Экспорт сохраняет зашифрованную копию. Импорт проверяет пароль и целостность копии, затем целиком заменяет текущее хранилище, включая настройки и мастер-пароль. Если старые записи нужны, сначала экспортируйте их. После смены мастер-пароля существующие копии продолжают открываться паролем, действовавшим при экспорте. Утерянный мастер-пароль восстановить невозможно.

## Сборка

Требуются CMake 3.21+, компилятор C++17, Qt 6.4+ с Qt Widgets, libsodium и OpenSSL 3 или новее для того же компилятора и архитектуры. AES-256-GCM выполняет OpenSSL с доступной на компьютере реализацией.

Пример для PowerShell с Qt MinGW, Ninja, OpenSSL и официальной статической библиотекой libsodium. Укажите пути к своим зависимостям. Компилятор, CMake и Ninja должны быть доступны в `PATH`.

```powershell
$qt = 'C:/Apps/Qt/6.12.0/mingw_64'
$sodium = 'C:/Dependencies/libsodium-win64'
$openssl = 'C:/Dependencies/openssl/mingw64'
$env:Path = "$qt/bin;$openssl/bin;$env:Path"
cmake -S . -B build -G Ninja "-DCMAKE_PREFIX_PATH=$qt" `
  "-DSODIUM_INCLUDE_DIR=$sodium/include" "-DSODIUM_LIBRARY=$sodium/lib/libsodium.a" `
  "-DOPENSSL_ROOT_DIR=$openssl" "-DOPENSSL_CRYPTO_LIBRARY=$openssl/lib/libcrypto.dll.a" `
  -DLOCALVAULT_SODIUM_STATIC=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
& "$qt/bin/windeployqt.exe" --release --translations ru build/LocalVault.exe
```

При распространении динамической сборки разместите DLL libcrypto рядом с EXE. Для динамической линковки libsodium укажите её импортную библиотеку, оставьте `LOCALVAULT_SODIUM_STATIC=OFF` и разместите DLL libsodium рядом с EXE. Тесты работают с отдельным временным каталогом и синтетическими данными.

Для сборки в Debian 12:

```sh
sudo apt install build-essential cmake ninja-build qt6-base-dev qt6-translations-l10n libsodium-dev libssl-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
cmake --install build --prefix "$HOME/.local"
```

## Архитектура

| Компонент | Назначение |
| --- | --- |
| `AuthManager` | Создаёт параметры хранилища и проверяет мастер-пароль |
| `CryptoManager` | Получает ключи, шифрует и аутентифицирует содержимое |
| `StorageManager` | Проверяет формат, читает файл и атомарно заменяет его через `QSaveFile` |
| `PasswordManager` | Управляет сессией, записями, настройками и резервными копиями |
| `PasswordGenerator` | Генерирует пароли на основе криптографического ГСЧ libsodium |
| `MainWindow` | Управляет интерфейсом, сеансом бездействия и буфером обмена |

## Формат и границы защиты

Порядок полей формата 1 — сигнатура `LVLT`, версия (32 бита), параметры Argon2id (число проходов и память в КиБ, по 32 бита), 16-байтовая соль, 32-байтовое проверочное значение, 32-байтовый случайный параметр получения ключа конкретной записи файла, 12-байтовый nonce, шифротекст, 16-байтовый тег AES-256-GCM и 32-байтовая контрольная сумма SHA-256. Многобайтовые числа хранятся в big-endian.

Argon2id 1.3 использует 64 МиБ и три прохода по умолчанию. Из результата libsodium KDF выводит отдельные ключи для шифрования и проверки пароля. Проверочное значение — HMAC-SHA-256 заголовочных параметров. Для каждого сохранения используются свежие случайные nonce и параметр производного ключа файла. AES-GCM аутентифицирует заголовок и содержимое. Контрольная сумма помогает обнаружить случайные повреждения до проверки пароля. Проверку подлинности выполняет AES-GCM.

Расшифрованные данные обрабатываются в памяти. Ключи хранятся в защищённой и заблокированной памяти libsodium. Приложение очищает подконтрольные буферы при завершении работы с ними. Qt, система ввода и буфер обмена могут создавать собственные копии. Защита файла рассчитана на хранение в закрытом состоянии. Доступ к разблокированному процессу, системным дампам, снимкам экрана и данным буфера зависит от защиты ОС и запущенных программ.

Справочные материалы — [Argon2id в libsodium](https://doc.libsodium.org/password_hashing/default_phf), [разделение ключей](https://doc.libsodium.org/key_derivation), [AES-GCM в EVP OpenSSL](https://docs.openssl.org/3.5/man3/EVP_EncryptInit/), [защищённая память](https://doc.libsodium.org/memory_management), [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html).
